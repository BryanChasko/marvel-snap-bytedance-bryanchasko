# Contributing

This project is maintained by Bryan Chasko with the HeraldStack multi-platform agent architecture.

## How to Contribute

1. Check the [open issues](https://github.com/BryanChasko/marvel-snap-bytedance-bryanchasko/issues) for available work
2. Fork the repo and create a branch from `main`
3. Follow the branch naming convention: `feat/`, `fix/`, `docs/`
4. Write specs before code (see `specs/SPEC-INDEX.md`)
5. Open a PR with a clear description

## Public Repo Rules

- No secrets, API keys, tokens, or credentials
- No PII (names, emails, phone numbers)
- No raw screenshots
- All external endpoints referenced by environment variable
- See [SECURITY.md](SECURITY.md) for full policy

## Spec-Driven Development

This project uses spec-driven development. Before writing code:

1. Check if a spec exists in `specs/`
2. If not, create one with EARS notation requirements
3. Tasks trace to requirements, commits trace to tasks
4. See [CONSTITUTION.md](CONSTITUTION.md) for architectural principles

## Code of Conduct

Be respectful. Haunting members are teammates with names and pronouns. See `.kiro/HAUNTING.md`.
